# 대시보드 UI 개선·검증 기록

> 2026-10-01: 이 기록의 대시보드는 콘솔로 대체되어 삭제됐다. 여기 적힌 화면·스타일·브라우저 검사(`theme-tokens`,
> `mock-preview` 등)는 지금 저장소에 없다. 콘솔의 구조와 브라우저 증명은 [web README](../web/README.md)를 본다.

## 변경 내용

- 공통 메뉴·헤더·테이블·버튼·입력창·상태 표시를 일관된 테마로 정리했다. 장식적 배경, 카드 이동 효과와 중복 CSS를 줄였다.
- 개요의 큰 요약 영역을 축소해 우선 대응 목록을 위로 올렸다. 기존 집계와 목록 순서는 유지했다.
- 탐지 목록의 상세 필터는 접을 수 있으며 적용된 필터는 밖에 남는다. 개별·전체 해제 후 첫 페이지와 검색 입력 초점으로 돌아간다.
- 모바일에서도 전체 검색을 사용할 수 있다. 결과를 선택하면 메뉴를 접고 도착 화면으로 초점을 이동한다.
- 비밀 메타데이터 행에 실제 버튼과 펼침 상태를 제공했다. 긴 AWS 계정·권한세트 이름과 모바일 스캔 차단 사유가 잘리지 않게 했다.
- 스캔 중지·탐지기 페이지 버튼의 클릭 영역을 보완했다. 기타 공급자 관리 목록의 요약·필터·작업 버튼과 좁은 화면의 표를 정리했다.
- 일부 데이터 조회 실패 안내는 계속 표시하며, 영향받은 영역의 오류 목록만 접을 수 있게 했다.

디자인 검토에는 `redesign-existing-projects`, `high-end-visual-design` 지침과
21st 디자인 MCP를 활용했다. 실제 로컬 Next 화면은 Playwright MCP로 확인했다.
외부 디자인 코드를 가져오거나 새 패키지를 설치하지 않았다.

## 탭과 하위 화면 확인 범위

단순히 탭이 렌더링되는지만 보지 않고 아래 클릭 경로를 기존 검사와 새 검사에 연결했다.
같은 컴포넌트의 모든 운영 레코드나 모든 오류 조합을 전수 검사했다는 뜻은 아니다.

공통으로 KO/EN, light/dark, 데스크톱/모바일, 메뉴, 검색 대화상자,
Escape·초점 복귀, 부분 데이터 오류의 펼침·접기를 확인했다.
실제 Next의 탐지 상세에서도 12개 펼침 영역과 11개 구역 링크를 직접 확인했다.

## 재현 가능한 검사

`web/`에서 실행한다. 모든 브라우저 검사는 합성 데이터와 로컬 정적 자산을 사용한다.

```text
npm test
npx tsc --noEmit
node scripts/theme-tokens.cjs --check
npm run build
npm run test:browser
```

- Node 테스트: **484개 통과**, 실패·skip 0.
- TypeScript와 프로덕션 빌드 통과. 생성된 dark 토큰 검사와 standalone의 sharp/libvips 미포함 검사 통과.
- 전체 합성 브라우저 검사 **24종 통과**. 최종 공급자 목록 스타일 수정 후 `provider-inventory`, `scoped-controls`, `dashboard-density`, `ui-shell-preview`와 기본 테스트 484개·타입·빌드도 재검증했다.
- `soc-queue`: 5개 폭(320/390/760/1024/1440) × 2개 언어 × 2개 테마. 필터 해제·페이지 초기화·키보드 초점 회귀 포함.
- `scoped-controls`: 4개 폭(320/390/760/1440) × 2개 언어 × 2개 테마. 긴 차단 사유, 버튼 영역, 비밀 행, AWS 이름과 비활성 버튼 확인.
- `ui-shell-preview`: 8개 조합에서 **80회 탭 방문·182개 화면 상태·1,110회 상호작용**.
  모든 조합은 주요 상세와 검색·오류 경로를 검사한다. EN/light/1440과 KO/dark/390은
  중첩 내용을 새로 탐색하며 각각 103개, 합계 **206회 펼침 컨트롤 검사**를 수행한다.
  누락된 GET 응답, 브라우저 런타임 오류, 예상하지 않은 외부 요청, 변경 요청은 0이었다.

브라우저 runner는 실패 시 종료 코드 1을 반환한다. 개별 검사만 실행하려면
`npm run test:browser -- ui-shell-preview`처럼 검사 이름을 전달한다.
미리보기 fixture의 v1/v2 URL과 실제 UI 응답 검증기 호환성도 `mock-preview.test.cjs`에서 검사한다.

## 유지한 경계와 한계

권한·승인·수집·자격증명 검증·SIEM·DB 계약은 변경하지 않았다.
부분 수집·권한 거절·미관측을 안전 또는 부재로 표시하지 않으며,
공급자가 저장한 ACTIVE와 실제 인증 검증, 발급처와 노출 소스, 인증 주체와 대응 담당자를 구분한다.
목록의 불러온 건수를 조직 전체 건수로 바꾸지 않았다.

실제 공급자 호출, 발견 자격증명 인증, 스캔·삭제·폐기, SIEM 전송, 운영 데이터와
실제 OIDC/SSO는 이번 UI 검증 대상이 아니다. 변경 작업을 다루는 기존 테스트도 합성 응답으로 검사한다.
프로덕션 빌드는 검증했지만 프로덕션 미리보기 서버 실행은 자동 승인 검토에서
“정책에 의해 차단”되어 실행하지 못했다. 실제 화면 확인에는 loopback 개발 서버와 합성 API를 사용했다.
이 기록은 운영 배포나 원격 CI 통과를 의미하지 않는다.

## 후속 정렬·잘림 점검 (2026-09-24)

기존 문서 너비 검사만으로는 패널 내부에서 숨겨지는 내용을 찾지 못했다.
실제 렌더링에서 다음 문제를 재현하고 소유 스타일에서 수정했다.

- Tailwind의 `.table` 유틸리티가 기존 div 스크롤 영역을 `display: table`로 바꿨다.
  공통 래퍼를 block으로 고정해 스캔·감사 표의 오른쪽 열까지 스크롤할 수 있게 했다.
  실제 HTML table의 레이아웃과 모바일 카드 보기는 유지한다.
- 768px 규칙 엔진 카드는 고정 최소 열 너비 때문에 폭 466px 안에 581px 내용을 넣고 있었다.
  유연한 열과 좁은 화면의 세로 배치로 바꿨다. 긴 설정 키·스캔 경로·실행 이름도 줄바꿈한다.
- 공급자 검증 토글의 긴 설치 설정 안내가 320px 패널 밖으로 잘렸다.
  체크박스와 본문을 분리한 grid로 바꾸고 안내를 본문 시작점에 정렬했다.
- 연결 지원 패널의 이중 제목 여백을 없애고 공통 패널 inset, 제목·본문·라벨·보조 글씨,
  코드 글꼴을 규칙·비밀 메타데이터·설정·연결·스캔·내부 검토 화면에 적용했다.
- 320px 폭·600px 높이·20px 기본 글씨에서 스캔 창의 고정 영역이 본문을 0 높이로 압축했다.
  낮은 화면에서는 창 전체가 스크롤되게 해 대상 선택부터 검토까지 접근하도록 했다.

확장한 `ui-shell-preview`는 320/390/768/1024/1440px × KO/EN × light/dark의
**20개 조합·200회 탭 방문·438개 상태·1,506회 상호작용**을 통과했다.
EN/light/320과 KO/dark/768에서 **206회 중첩 펼침 컨트롤 검사**를 수행했다.
패널 안의 텍스트 잘림, 코드 글꼴, 제목 inset, 스크롤 영역의 실제 display와 마지막 열 접근을
회귀 조건으로 추가했다. 누락 GET·런타임 오류·외부 요청·변경 요청은 0이었다.
별도 합성 점검에서는 규칙·비밀·설정·교체 관리 50상태와 스캔 reflow 80상태를 확인했다.
스캔 reflow는 5개 폭, 두 언어, 16/20px 글씨를 포함하며 공급자 요청을 실행하지 않았다.

후속 검사에서 shell fixture가 잘못된 테마 저장키를 사용해 기존 dark 표기가 실제 다크
화면을 보증하지 못했음을 확인했다. 제품의 저장키·초기화 스크립트를 재사용하도록 고치고
저장값·선택값·실제 배경색까지 검사한 뒤 위 20개 조합을 다시 통과했다.
이 재검증이 기존 shell의 다크 테마 근거를 대체한다.
Node 484개·타입 검사·프로덕션 빌드·브라우저 24종이 통과했다.
마지막 공급자 사건 표에 기존 접근 가능한 스크롤 래퍼를 적용한 뒤에는
`audit-details`, `provider-inventory`를 다시 통과했다.
